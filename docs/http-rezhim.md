# HTTP-режим: запуск и эксплуатация

Служба `api.py` — тонкая обёртка FastAPI над ядром `anonymizer.py`. Ядро она не
меняет: те же слои, те же ключи, тот же `restore`.

⛔ **Контур.** Служба обрабатывает чужие персональные данные. Место её жизни —
сервер в РФ, доступ — из внутренней сети или через обратный прокси с TLS.
Слушать `0.0.0.0` без прокси и без TLS нельзя: токен уйдёт открытым текстом.

---

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-api.txt
```

`natasha` и `pymorphy3` для HTTP-режима **обязательны**, хотя для самого ядра
они мягкие. Причина в разделе «Вердикт готовности» ниже.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `ANONYMIZER_TOKEN` | — (**обязательна**) | Токен доступа. **Без неё служба не стартует** — проверено кодом возврата 1 у `uvicorn`. Открытая служба обезличивания принимает чужие ПДн от кого угодно. |
| `ANONYMIZER_MAX_BODY` | `262144` | Предел тела запроса в байтах. Больше — отказ `413`. |
| `ANONYMIZER_LOG_LEVEL` | `INFO` | Уровень журнала. |
| `ANONYMIZER_DOCS` | — | `1` включает `/docs` и `/openapi.json`. По умолчанию закрыты: лишняя открытая точка у службы с ПДн. |

Токен — случайные 32+ символа, например `python3 -c "import secrets;
print(secrets.token_urlsafe(32))"`. Хранить рядом с прочими ключами, в файле
с правами `0600`, не в командной строке (её видно в `ps`).

## Запуск

```bash
ANONYMIZER_TOKEN=… .venv/bin/uvicorn api:app --host 127.0.0.1 --port 8081
```

`--host 127.0.0.1` — намеренно: наружу служба выходит только через прокси.

## Эндпоинты

### `POST /anonymize`

```json
{"text": "…", "use_ner": true, "use_dict": true}
```

Ответ:

```json
{"text": "…", "keys": {"[ФИО_1]": {"original": "…", "type": "ФИО"}},
 "stats": {"total": 4, "by_type": {"fio": 1, "address": 1}}}
```

- `use_ner` управляет **двумя** слоями сразу — нейросетевым и словарным добором
  фамилий. Так устроено ядро, и семантика намеренно не расходится.
- `use_dict` — личный словарь клиентов (`словарь_клиентов.txt` рядом с ядром).
- ⛔ **Ключи возвращаются вызывающему и больше нигде не хранятся.** Ни файла, ни
  кеша, ни базы. Потерял ключи — расшифровать нечем; это свойство, а не изъян.

### `POST /restore`

```json
{"text": "…", "keys": {"[ФИО_1]": {"original": "…", "type": "ФИО"}}}
```

Ответ: `{"text": "…"}`.

### `GET /health`

Без токена — это точка мониторинга.

```json
{"status": "ok", "ready": true,
 "ner_status": "включён (Natasha)", "surnames_status": "включён (pymorphy3)",
 "dict_status": "пусто — словарь_клиентов.txt",
 "version": "1.0.0", "core_fingerprint": "b4240940e77e"}
```

`core_fingerprint` — первые 12 знаков sha256 файла ядра. Нужен, чтобы отличить
«выкачено» от «кажется, выкачено»: сравнивается с локальным
`shasum -a 256 anonymizer.py`, содержимое по ssh читать не нужно.

## Вердикт готовности: почему `ready` отдельным полем

Без `pymorphy3` словарный слой отключается **без ошибки**. Ядро работает,
запросы проходят, ответы приходят — а утечка (фамилии, которые NER пропускает
точечно) возвращается незаметно. Поэтому:

- `ready: false` — машинный вердикт для сборщика метрик;
- HTTP **503** на `/health` — для проверки живости, которая тела не разбирает;
- `POST /anonymize` с `use_ner: true` при неполном щите — **отказ 503**, а не
  тихая работа без слоя.

Явный `use_ner: false` отказа не вызывает: это осознанный выбор вызывающего,
а не молчаливая поломка.

## Что не попадает в журнал и в ответы

- Ни входного текста, ни ключей, ни фрагментов значений — только счётчики:
  `anonymize: символов=94, масок=4, типов=4, мс=11`.
- Текст исключения наружу не уходит: отдаётся только класс
  (`обработка не выполнена (RuntimeError)`). Причина — движок кладёт в сообщение
  об ошибке фрагмент разбираемых данных.
- Штатный обработчик ошибок валидации FastAPI возвращает присланное значение
  целиком; он заменён своим, который называет только имя поля и код ошибки.
- ⚠️ Текст никогда не передавать в query-строке: её пишет access-лог uvicorn.

## Пример unit-файла systemd

⛔ Ниже — **образец для документации**, на сервере он не применён. Пути, имя
пользователя и порт подставить свои.

```ini
[Unit]
Description=Обезличиватель — HTTP-режим
After=network.target

[Service]
Type=simple
User=anonymizer
WorkingDirectory=/srv/anonymizer
# Файл с токеном: права 0600, владелец — тот же пользователь.
EnvironmentFile=/etc/anonymizer/api.env
ExecStart=/srv/anonymizer/.venv/bin/uvicorn api:app --host 127.0.0.1 --port 8081
Restart=on-failure
RestartSec=5
# Служба ничего не пишет на диск — ключи живут только в памяти запроса.
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
NoNewPrivileges=yes

[Install]
WantedBy=multi-user.target
```

⚠️ `ProtectSystem=strict` делает файловую систему доступной только на чтение —
это не украшение, а сторож инварианта «ключи на диск не пишутся»: попытка
записи упрётся в отказ ядра ОС, а не в добрую волю кода.

⚠️ После выката проверять **вызовом**, а не глазами:

```bash
curl -sf http://127.0.0.1:8081/health | grep -q '"ready":true' || echo "ЩИТ НЕПОЛОН"
```

## Тесты

```bash
<venv-с-fastapi>/bin/python -m unittest discover tests -v
```

⚠️ **Без `fastapi` файл `tests/test_api.py` целиком уходит в `skip`, а прогон
рапортует `OK`.** Увидев skip, считать HTTP-режим непроверенным. Ядровый venv
(тот, где стоит natasha) специально не содержит fastapi — тесты ядра и тесты
транспорта гоняются разными окружениями.
